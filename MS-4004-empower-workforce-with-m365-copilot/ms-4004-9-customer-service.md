
# Microsoft Copilot Customer Service向けデモ：演習2

## デモの概要

カスタマーサービス担当者が、顧客から製品・サービスに関する問い合わせを受けた場面を想定します。

Microsoft Copilotを使用して、問い合わせ内容の整理、トラブルシューティング、回答案の作成、対応内容のナレッジ化までを進めます。

1. 顧客からの問い合わせ内容を整理する
2. トラブルシューティングを行う
3. 顧客向けの回答を作成する
4. 対応内容をナレッジとして整理する

> **デモの流れ：Understand → Troubleshoot → Respond → Learn**

デモの実施時間は合計50分です。

# 演習2-1：問い合わせ内容を整理する

## 使用するアプリ

[Microsoft 365 Copilot Chatを開く](https://copilot.cloud.microsoft/home)

## シチュエーション

顧客から次のような問い合わせを受けたとします。

> クラウドサービスにサインインできなくなりました。
> 昨日までは問題なく利用できていました。
> サインインするとエラーが表示されます。
> 業務で使用しているため、できるだけ早く解決したいです。

まだ情報が不足しているため、いきなり原因を決めつけず、問題を切り分けるための確認事項をCopilotと整理します。

## プロンプト

```text
顧客から以下の問い合わせがありました。

「クラウドサービスにサインインできなくなりました。
昨日までは問題なく利用できていました。
サインインするとエラーが表示されます。
業務で使用しているため、できるだけ早く解決したいです。」

カスタマーサービス担当者として、この問題を切り分けるために顧客へ確認すべき事項を整理してください。

以下の観点を含めてください。

1. 問題が発生し始めた時期
2. 影響を受けているユーザーの範囲
3. 使用している端末やアプリ
4. 表示されているエラーメッセージ
5. 最近行われた変更
6. すでに実施した確認や対処
7. 業務への影響

この段階では原因を断定せず、追加で確認すべき質問を優先順位付きで整理してください。
```

## 想定する結果

問題を切り分けるための質問が整理されます。

例えば以下のような観点です。

- 1人だけか、複数ユーザーか
- Web版でも発生するか
- 別の端末でも再現するか
- 正確なエラーメッセージは何か
- パスワードやアカウント設定を最近変更したか
- ネットワーク環境を変えても発生するか
- 業務が完全に停止しているか

> この段階で重要なのは、Copilotにすぐ答えを出させることではなく、問題解決に必要な情報を整理することです。

# 演習2-2：トラブルシューティングを行う

## 使用するアプリ

[Microsoft 365 Copilot Chatを開く](https://copilot.cloud.microsoft/home)

## シチュエーション

追加確認の結果、次のことが分かったとします。

- 問題は1人のユーザーだけで発生している
- 昨日までは利用できていた
- Webブラウザーからもサインインできない
- 別のユーザーは同じサービスを正常に利用できる
- ネットワーク接続自体には問題がない
- 最近パスワードを変更した
- エラーメッセージが表示される

この情報から、考えられる原因と安全な確認手順を整理します。

## プロンプト

```text
追加確認の結果、次のことが分かりました。

- 問題は1人のユーザーだけで発生しています
- 昨日までは利用できていました
- Webブラウザーからもサインインできません
- 別のユーザーは同じサービスを正常に利用できます
- ネットワーク接続自体には問題ありません
- ユーザーは最近パスワードを変更しています
- サインイン時にエラーメッセージが表示されます

この情報から考えられる原因候補と、確認すべきトラブルシューティング手順を整理してください。

以下の形式にしてください。

1. 考えられる原因
2. その原因を疑う理由
3. 確認方法
4. 問題が解決しなかった場合の次の確認

影響が小さく、安全な確認から順番に実施できるようにしてください。

情報が不足している場合は原因を断定せず、追加で確認すべき内容を示してください。
```

## 想定する結果

可能性のある原因と、問題を段階的に切り分ける手順が整理されます。

ポイントは、単に「これが原因です」と回答させるのではなく、

**仮説 → 確認 → 結果 → 次の仮説**

というトラブルシューティングの考え方を支援させることです。

## 追加プロンプト

```text
顧客への影響をできる限り小さくするため、最初に実施すべき確認を3つに絞ってください。

それぞれの確認によって何を切り分けられるのかも説明してください。
```

# 演習2-3：顧客向け回答を作成する

## 使用するアプリ

[Outlookメールを開く](https://outlook.cloud.microsoft/mail/)

## シチュエーション

確認すべき内容とトラブルシューティングの方向性が整理できました。

次に、顧客へ実施してもらいたい確認事項を、新規メールとして作成します。

既存メールスレッドは使用しません。

## プロンプト

```text
クラウドサービスにサインインできないというお問い合わせをいただいたお客様への返信メールを作成してください。

現在、次の状況が分かっています。

- 問題は1人のユーザーだけで発生しています
- 昨日までは利用できていました
- Webブラウザーからもサインインできません
- 別のユーザーは正常に利用できます
- 最近パスワードを変更しています

メールには以下を含めてください。

1. お問い合わせへのお礼
2. 現在確認できている状況
3. お客様に追加で確認していただきたい事項
4. 確認結果を返信していただきたいこと
5. 問題が継続する場合は引き続き対応すること

原因が確定していないため、断定的な表現は避けてください。

ITに詳しくないお客様でも理解できる、丁寧で簡潔な日本語にしてください。
```

## 想定する結果

Outlookに、顧客へそのまま送付する前にレビューできるメールの下書きが作成されます。

ここでは、

**技術者向けのトラブルシューティング情報**

から、

**顧客が理解・実行できるコミュニケーション**

へ変換できることを確認します。

## 追加プロンプト：短くする

```text
内容を維持したまま、メールをもう少し短くしてください。
```

## 追加プロンプト：より分かりやすくする

```text
技術的な表現を減らし、お客様が実施する操作を番号付きの手順にしてください。
```

# 演習2-4：対応内容をナレッジ化する

## 使用するアプリ

[Wordを開く](https://word.cloud.microsoft/)

## シチュエーション

今回の問い合わせ対応が完了したとします。

同様の問い合わせが発生した場合に、別の担当者でも対応できるように、トラブルシューティングの内容をナレッジ記事として整理します。

既存ファイルは使用せず、新しいWord文書から作成します。

## プロンプト

```text
「クラウドサービスにサインインできない」という問い合わせについて、カスタマーサービス担当者向けのナレッジ記事を作成してください。

以下の構成にしてください。

1. 症状
2. 最初に確認する事項
3. 主な原因候補
4. トラブルシューティング手順
5. 顧客に確認してもらう事項
6. 解決しない場合の追加確認
7. 専門担当者へエスカレーションすべき条件
8. 対応時の注意事項

原因を一つに決めつけず、状況を確認しながら問題を切り分けられる内容にしてください。

新しく担当するカスタマーサービス担当者でも使用できる、簡潔で実践的な文書にしてください。
```

## 想定する結果

Wordに再利用可能なナレッジ記事のドラフトが生成されます。

例えば以下が整理されます。

- 症状
- 初期確認
- 原因候補
- 切り分け手順
- 顧客に依頼する確認
- エスカレーション条件
- 注意事項

## 追加プロンプト

```text
担当者が問い合わせ対応中に短時間で確認できるように、冒頭に「最初に確認する5項目」のチェックリストを追加してください。
```

# 演習2のまとめ

このデモでは、カスタマーサービス担当者が問い合わせを受けてから、対応内容を再利用可能なナレッジにするまでを体験しました。

| 段階 | カスタマーサービス業務 | 使用するツール |
|---|---|---|
| **Understand** | 問い合わせ内容を整理し、不足している情報を確認する | [Microsoft 365 Copilot Chat](https://copilot.cloud.microsoft/home) |
| **Troubleshoot** | 原因候補と確認手順を整理する | [Microsoft 365 Copilot Chat](https://copilot.cloud.microsoft/home) |
| **Respond** | 顧客が理解できる回答を作成する | [Outlookメール](https://outlook.cloud.microsoft/mail/) |
| **Learn** | 対応方法を再利用可能なナレッジにする | [Word](https://word.cloud.microsoft/) |

> Copilotに問題解決そのものを任せるのではなく、状況を整理し、仮説を立て、安全に確認し、その結果を顧客や他の担当者に分かりやすく伝えることが、この演習のポイントです。

---

# デモ実施上のポイント

この演習では、実際の顧客情報や問い合わせ履歴を使用しません。

- 実際の顧客データ：使用しない
- 既存Outlookメール：使用しない
- 既存Teamsチャット：使用しない
- 実際のサポートチケット：使用しない
- 既存のナレッジ記事：使用しない

演習用の問い合わせ内容そのものをプロンプトに含めることで、事前のデータ準備を最小限にしています。

また、トラブルシューティングではCopilotの回答だけを根拠に実際のシステム変更を行うのではなく、製品の公式ドキュメントや組織のサポート手順などを確認したうえで対応することが重要です。
