
# Microsoft Copilot Operations向けデモ：演習1

## デモの概要

業務部門の担当者が、日常的な業務プロセスを見直し、改善案を検討する場面を想定します。

Microsoft Copilotを使用して、現在の業務を整理し、課題を分析し、改善案を検討し、関係者向けに説明できる形へまとめていきます。

1. 現在の業務プロセスを整理する
2. 現状と改善後のプロセスを比較する
3. 業務改善案を作成する
4. 関係者向けに改善案をまとめる

> **デモの流れ：Visualize → Compare → Improve → Communicate**

デモの実施時間は合計50分です。

# 演習1-1：業務プロセスを可視化する

## 使用するアプリ

[Microsoft Whiteboard](https://whiteboard.cloud.microsoft/)

## シチュエーション

社内の問い合わせ対応業務を見直すことになりました。

まず、問い合わせを受け付けてから回答し、対応を終了するまでの一般的な業務プロセスを整理します。

特定の社内システムや実際の業務データは使用せず、一般的な問い合わせ対応業務を例にします。

## プロンプト

```text
社内の問い合わせ対応業務について、現在の一般的な業務プロセスを整理してください。

次のような流れを含めてください。

1. 問い合わせの受付
2. 問い合わせ内容の確認
3. 担当者の決定
4. 必要な情報の調査
5. 回答案の作成
6. 問い合わせ元への回答
7. 必要に応じた追加対応
8. 対応完了

各ステップについて、担当者が行う代表的な作業も追加してください。

業務改善について議論するためのたたき台として、シンプルで分かりやすく整理してください。
```

## 想定する結果

問い合わせ対応業務が、複数のステップとして視覚的に整理されます。

例えば以下のようなポイントを確認できます。

- どこで人による判断が必要か
- どこで情報検索が必要か
- どこで待ち時間が発生しやすいか
- どこに繰り返し作業があるか
- どの部分を改善できそうか

> Whiteboardでは、完成した業務フローを作ることよりも、Copilotが作成したたたき台を人間がレビューし、議論できる状態にすることを重視します。

# 演習1-2：現在と改善後の業務を比較する

## 使用するアプリ

[Microsoft 365 Copilot Chatを開く](https://copilot.cloud.microsoft/home)

## シチュエーション

現在の問い合わせ対応プロセスを確認したところ、情報検索、回答作成、担当者への引き継ぎなどに時間がかかっている可能性があることが分かりました。

次にCopilotと相談し、手作業を減らした場合に業務プロセスがどのように変わるか考えます。

## プロンプト

```text
社内の問い合わせ対応業務を改善したいと考えています。

現在は、問い合わせを受け付けた後、担当者が問い合わせ内容を確認し、必要な情報を探し、回答を作成して、問い合わせ元へ回答しています。

この業務を改善する場合について、

1. 現在の業務
2. 改善できる可能性のあるポイント
3. 改善後の業務
4. 期待される効果
5. 人間による確認や判断を引き続き残すべきポイント

を比較できるように表形式で整理してください。

単純にすべてを自動化するのではなく、人が判断すべき業務と、効率化できる業務を区別してください。
```

## 想定する結果

現在の業務と改善後の業務が比較されます。

例えば次のような改善候補が整理されます。

- 問い合わせ内容の整理
- 関連情報の検索
- 回答案の作成
- 過去の問い合わせとの比較
- 対応内容の要約
- ナレッジ化

同時に、次のような人による判断が必要な業務も整理します。

- 回答内容の最終確認
- 例外的な問い合わせへの対応
- 優先順位の判断
- 組織としての意思決定

## 追加プロンプト

```text
この中から、比較的導入しやすく、業務時間の削減効果も期待できる改善案を3つ選んでください。

それぞれについて、

- 現在の課題
- 改善方法
- 期待される効果
- 導入時の注意点

を整理してください。
```

# 演習1-3：業務改善案を文書化する

## 使用するアプリ

[Wordを開く](https://word.cloud.microsoft/)

## シチュエーション

問い合わせ対応業務の改善ポイントが整理できました。

次に、関係者と改善内容を検討するための「業務改善案」を作成します。

既存の社内文書は使用せず、新しいWord文書から作成します。

## プロンプト

```text
社内の問い合わせ対応業務について、業務改善案を作成してください。

現在は、問い合わせを受け付けた後、担当者が内容を確認し、必要な情報を探し、回答を作成しています。

特に、情報検索、回答案の作成、対応内容の整理などに時間がかかっていることを想定してください。

以下の構成で作成してください。

1. 背景
2. 現在の業務プロセス
3. 現在想定される課題
4. 改善の方向性
5. 改善後の業務プロセス
6. 期待される効果
7. 導入時に確認すべき事項
8. 次のステップ

具体的な組織固有の情報は断定せず、実際の業務状況を確認する必要がある項目は「要確認」としてください。

業務担当者とマネージャーの両方が理解できる、簡潔で実践的な内容にしてください。
```

## 想定する結果

Wordに、業務改善について関係者と議論するための文書が作成されます。

例えば以下の内容が整理されます。

- 現在の業務
- ボトルネックとなる可能性のある作業
- 改善候補
- 人間の判断を残すポイント
- 期待される効果
- 導入時の注意事項
- 次のアクション

## 追加プロンプト：改善前後を分かりやすくする

```text
「現在の業務」と「改善後の業務」の違いが分かりやすいように、Before / After形式の表を追加してください。
```

## 追加プロンプト：マネージャー向けに短くする

```text
この文書の冒頭に、マネージャーが1分程度で読めるエグゼクティブサマリーを追加してください。
```

# 演習1-4：関係者向けの説明資料を作成する

## 使用するアプリ

[PowerPointを開く](https://powerpoint.cloud.microsoft/)

## シチュエーション

業務改善の方向性が整理できました。

次に、マネージャーや関係部門との打ち合わせで使用する、短い説明資料を作成します。

## プロンプト

```text
社内の問い合わせ対応業務の改善について、関係者向けの説明資料を作成してください。

次の内容を含めてください。

1. 現在の問い合わせ対応業務
2. 現在想定される主な課題
3. 改善の方向性
4. 現在と改善後の業務の違い
5. 期待される効果
6. 人による確認や判断を継続すべきポイント
7. 次のステップ

10分以内で説明できる簡潔なプレゼンテーションにしてください。

細かな技術説明ではなく、業務がどのように変わるのかが関係者に伝わる内容を優先してください。
```

## 想定する結果

PowerPointに、例えば次のような構成の資料が作成されます。

1. 業務改善の背景
2. 現在の問い合わせ対応
3. 現在の課題
4. 改善案
5. Before / After
6. 期待される効果
7. 人間が判断する領域
8. 次のステップ

## 追加プロンプト

```text
現在の業務と改善後の業務の違いが一目で理解できるように、Before / Afterを中心とした構成に変更してください。
```

# 演習1のまとめ

このデモでは、業務担当者が日常業務を改善する場面を想定し、Microsoft Copilotを次のように利用しました。

| 段階 | 業務 | 使用するツール |
|---|---|---|
| **Visualize** | 現在の業務プロセスを可視化する | Microsoft Whiteboard |
| **Compare** | 現在と改善後の業務を比較する | [Microsoft 365 Copilot Chat](https://copilot.cloud.microsoft/home) |
| **Improve** | 業務改善案を文書化する | [Word](https://word.cloud.microsoft/) |
| **Communicate** | 関係者向けに改善案を説明する | [PowerPoint](https://powerpoint.cloud.microsoft/) |

> Copilotに業務改善の判断そのものを任せるのではなく、現在の業務を整理し、改善の可能性を検討し、関係者と議論できる形にすることが、この演習のポイントです。

---

# デモ実施上のポイント

この演習では、できるだけデモ専用データを事前準備しなくても実施できるようにしています。

- 既存のTeamsチャット：使用しない
- 既存のOutlookメール：使用しない
- 既存の業務文書：使用しない
- 実際の問い合わせ履歴：使用しない
- 実際の顧客データ：使用しない

そのため、参加者の環境や実データに依存せず、同じストーリーでデモを再現できます。

また、実際の業務改善では組織固有の業務プロセス、ルール、システム、データなどを確認したうえで、Copilotの提案を人が検証する必要があります。
